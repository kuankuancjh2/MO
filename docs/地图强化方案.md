## 0. 参考图拆解：它到底"细节"在哪

我把图按区域读了一遍，提取出 6 条可执行的规则。这是整份方案的地基。

### 规则 1：地体是"厚岩体"，不是三行薄片

图里的地面是一条**4~6 行深的实心岩体**：最上面 1 行是地表砖，下面 3~5 行是内部砖，
而且**内部材质会变化**（一段是素石、一段是砖砌 桥墩）。地体内部还被**挖出了拱形空腔**
（水道上方的连拱），所以它看起来是"有构造的堤坝"，而不是"一块色块"。

> 我现在的岛只有 3 行厚、内部完全同质 → 这就是"无聊的三行块"的根源。

### 规则 2：建筑长在地体**上面**，天际线才是记忆点

图最抓眼的是**天际线**：尖顶塔 → 带雉堞的城墙 → 拱门 → 绿顶塔 → 又一段城墙 → 梯子。
高度起伏 + 屋顶造型（尖顶/圆顶/平顶雉堞）让这个地图像"一个地方"。

> 我现在的岛上几乎什么都没有 → 天际线是一条平线。

### 规则 3：桥是"组合件"，不是一条板

图中间的桥 = **栏杆立柱（走道）+ 石砌桥墩 + 桥墩上的拱洞 + 桥下水面**。
四件东西叠起来才叫桥。

> 我现在是一条 1 格厚的木板 → 这就是"莫名其妙的桥"。

### 规则 4：装饰极密，但全部无碰撞

云、招牌（挂着一颗心）、信封、魔杖、箭头、树、灌木、陶罐、锯齿、栅栏……
**密度比地形本身还高**，但玩家一个都碰不到。地图的"信息量"主要来自这一层。

### 规则 5：整体黑白线稿，只有"活物"带颜色

地形/建筑全是白填充 + 黑描边 + 浅灰细节；**只有角色和少数道具是彩色的**
（红脸、紫脸、黄脸、绿屋顶、黄磁铁、青信箱）。所以眼睛自动把"线稿"读成背景、
把"彩色"读成主体。

> **这条直接印证了你的决定**：黑白墨线的世界 + 彩色的汉字敌人。地图是纸，字是墨和朱。

### 规则 6：背景是无描边的灰剪影

云和远处的树**只有浅灰、没有黑描边** → 天然的视差层。
（我抽看素材时确认过：`background_*` 就是这样的。）

## 1. 美术方向（确认版）

| 元素 | 处理 | 素材 |
|---|---|---|
| **地图（地形/建筑/装饰）** | **纯黑白线稿**：白填充 + 黑描边 + 浅灰内部 | `tile_*` `castle` `tower` `column*` `roof*` `archway*` `plank` `fence` `pole*` |
| **背景** | 浅灰无描边剪影，三层视差 | `background_cloud*` `background_tree*` |
| **主角「莫」** | **黑墨字**，会变成 慕/暮/漠/蟆… 就像书写 | 字体渲染（保持现在） |
| **普通敌人** | **彩色汉字**（命/乐/色/名…），一色一字 | 字体渲染 + 颜色 |
| **偏旁怪** | **空心（描边）字**，和实心敌人区分开 | 字体渲染 + 只有描边 |
| **偏旁（地里捡的）** | **黑白单个偏旁字**，不做彩色光球 | 字体渲染 |
| **UI** | 手绘数字 + 框 | `ui_num0..9` `ui_box` `ui_button` `ui_select` `tile_coin` `tile_heart` |

> **关键审美原则**：世界是黑白线稿，**只有"活着的字"有颜色**。
> 莫是黑墨（无），敌人是彩墨（有） —— 连色彩都在讲主题。

## 2. 敌人汉字化（新设计）

主题：`莫` = **无**。那敌人就该是**"有"**——一切"不肯消失的东西"。
名字就是它们的性格，颜色就是它们的类别。**不再是清一色红。**

### 2.1 普通敌人 = 彩色汉字（10 种）

| 字 | 概念 | 颜色 | 行为 | 对应现在的 |
|---|---|---|---|---|
| **命** | 生命 | 朱红 | 地面巡逻，血最厚（要打好几下） | 方块怪 |
| **乐** | 快乐 | 明黄 | 弹跳移动（跳着走），踩着它像坐跳床 | 新 |
| **色** | 形色 | 紫 | 追着你跑（猎手） | 猎手 |
| **名** | 名声 | 青 | 飞（飞怪），会飘到你上方 | 飞怪 |
| **利** | 利益 | 绿 | 掉很多金币（打了划算） | 新 |
| **权** | 权力 | 橙 | 精英：血厚 + 伤害高 + 体型大 | 新 |
| **欲** | 欲望 | 粉 | 会**把你吸过去**（反向的磁吸） | 新 |
| **妄** | 虚妄 | 灰 | 会分身（看起来 3 个，只有 1 个能打） | 新 |
| **累** | 负担 | 褐 | 光环：附近的方块消失更快 | 新 |
| **有** | 存在 | **黑白巨大** | **Boss**（它不停地"造"，你把它抹掉） | Boss |

> 颜色分工：**红=危险硬碰 / 黄=轻快 / 紫=追人 / 青=空中 / 绿=诱惑 / 橙=精英 /
> 粉=拉扯 / 灰=欺骗 / 褐=环境 / 黑白=Boss**。玩家看一眼颜色就知道该怎么应对。

### 2.2 偏旁怪（保留，是另一类）

**偏旁怪 = 空心描边字**（如空心的「日」「土」），和实心彩字形成"另一种东西"的对比。
它不扣血，碰到给你一个正/负临时效果（沿用现在 4 种：心/月/日/土）。
空心 = "不完整的字"，正好是"偏旁"的意思。

### 2.3 汉字敌人怎么画

字体渲染 + 描边（`Label` 的 `font_outline_*`）+ 颜色，**不需要新素材**。
加一点参考图里的"活物感"：字下方两只小眼睛 + 随移动轻微倾斜（现在主角已有类似处理）。
要不要加眼睛，见第 11 节问题 3。

## 4. 地图细节语法（把参考图变成生成规则）

### 4.1 地体做厚 + 内部有构造

| 参数 | 现在 | 改成 |
|---|---|---|
| 岛厚度 | 3 行（固定） | **4~7 行**，按岛的横向长度插值（短岛薄、长岛厚） |
| 表层 | 1 行 | 1 行地表砖（按 biome） |
| 内部 | 同质 | **2~5 行内部砖**，且**分段换材质**（素石 / 砖砌：每 6~10 列换一次，用确定性随机） |
| 内部空腔 | 无 | 长岛的厚地体里**挖拱形空腔**（`bridge_arch` / `tile_arch*` 反用），做成"连拱堤坝"的观感 —— **纯视觉，不改碰撞** |

> 这一步做完，"无聊的三行块"就没了：走在上面看不出，但视线一落到崖边就能看到
> 地体的内部构造和拱洞。

### 4.2 天际线（建筑长在岛上）

岛的**地表上方**按位置长出建筑构件，形成起伏剪影：

| 构件 | 素材 | 尺寸 | 频率 |
|---|---|---|---|
| 尖顶塔 | `tower` + `tower_top` + `roof_roundA` | 2~3 列 × 4~6 行 | 稀（每 60~90 列） |
| 雉堞城墙 | `castle` `castle_top` `tile_castle` | 3~8 列 × 2~3 行 | 中 |
| 拱门 | `archway_small` / `archway_small_decorative` | 3 列 × 3 行 | 中 |
| 立柱 | `column_top/middle/bottom` | 1 列 × 2~4 行 | 密 |
| 屋顶 | `roof` `roof_roundA..E` `roof_round_half` | 3~5 列 | 中 |
| 门窗 | `window` `window_round` `doorway_open/closed` | 1 列 | 密（贴在墙上） |
| 树 | `tile_tree` + `tile_treeTop` | 1~2 列 × 2 行 | 密（草原） |
| 梯子 | `tile_ladder` | 1 列 × 3~6 行 | 稀 |

### 4.3 桥的组合化（四件套）

我现在已经知道"这一列是桥 + 缺口左右两端是谁"，据此：

| 位置 | 素材 | 说明 |
|---|---|---|
| 桥面 | `bridge_walkway`（贴单元格顶部）+ `pole` 当栏杆柱（每 3 列一根） | |
| 两端 | `bridge_column` | 桥墩，落在岛的地体上 |
| 桥下 1~2 行 | `bridge_arch` / `bridge_arch_bottom` | 拱形支撑，悬空 |
| 桥下更低 | `tile_water` | 水面（见 4.5） |

> 于是桥从"一条板"变成"一座桥"。**碰撞完全不变**（还是 1 格厚的可站面）。

### 4.4 三级密度（解决"结构太少"）

现在只有一个槽位周期（34 列 × 55% ≈ 每 62 列一个）→ 太稀。改成**三级**：

| 级别 | 周期 | 内容 | 目标密度 |
|---|---|---|---|
| **微装饰** | 每 4~10 列 | 灌木 `tile_bush` `tile_bushHalf` · 树 `tile_tree` · 陶罐 `pottery` · 招牌 `tile_blockWindow` · 箭头 `tile_arrow*` · 栅栏 `fence` · 灯杆 `pole_lantern` · 地毯 `carpet` · 仙人掌 `cactus` · 星 `star` | **每屏十几个**（无碰撞） |
| **小结构** | 每 15~25 列 | 拱门 · 碑 · 柱廊 · 悬字台 · 单格梯子 · 箱子 | **每屏 1~2 个** |
| **大结构** | 每 60~90 列 | 小屋 · 塔（可进）· 城门 · 集市 · 有之殿 | **每 3 屏 1 个** |

三级用**三个独立的槽位周期和概率** —— 这样地图"很密但不挤"。

### 4.5 水（注水）

断崖的**最底 1~2 行** + 桥下方 → `tile_water`，水面可加 `smoke` 做雾气。
掉进断崖从"掉进虚空"变成"掉进水里"，落点心理完全不同。**纯视觉，低风险。**

### 4.6 城堡能不能进？（两种都做）

| 变体 | 做法 |
|---|---|
| **装饰立面**（不能进） | 墙体 + 雉堞 + 窗 + 门拱，玩家走过路过看看 |
| **可进入**（能进） | 用我现在的字符网格：**地面层左右贯通**（保持可通过），中空 1~2 行做室内，墙上开 `doorway_open`，室内放梯子/箱子/藏字砖；屋顶用 `roof_*` |

> 两者都靠同一个结构系统生成，只是网格不同。可进入的城堡是"室内"，
> 因为有梯子（第 6 章）才真的有意思。

## 5. 过采样（素材原生尺寸 + 镜头拉远）

你的说法完全对，我按这个来。**素材原样 128px 放进去，格子 = 128，镜头 zoom 拉回 0.375。**

### 5.1 为什么等价

| | 现在 | 改后 |
|---|---|---|
| 格子 | 48 px | **128 px** |
| 相机 zoom | 1.0 | **0.375** (= 48/128) |
| 一屏可见 | 26.7 × 15 格 | 26.7 × 15 格（**一样**） |
| 素材缩放 | 128→48 逐张缩 | **1:1 原生**，由 GPU 在绘制时过滤 |

布局、手感、可见范围**完全不变**，但素材是原生尺寸送进渲染管线的
（配合 mipmap + `Linear Mipmap` 过滤，就是你说的过采样效果）。

### 5.2 需要 ×2.667 的常量（`BalanceData`）

比例 `k = 128/48 = 2.6667`。**只改"像素长度"，时间类的一律不动。**

| 类型 | 字段 | 现在 → 改后 |
|---|---|---|
| 长度 | `tile_size` | 48 → **128** |
| 长度 | `player_size` | 32 → **86** |
| 加速度 | `gravity` | 1500 → **4000** |
| 速度 | `max_fall_speed` | 950 → **2533** |
| 速度 | `move_speed` | 250 → **667** |
| 加速度 | `accel` / `friction` | 2400 / 2800 → **6400 / 7467** |
| 速度 | `jump_velocity` | −520 → **−1387** |
| 速度 | `projectile_speed` | 680 → **1813** |
| 长度 | `attract_radius` | 230 → **613** |
| 速度 | `attract_speed` | 420 → **1120** |
| 速度 | `enemy_speed` | 68 → **181** |
| 速度 | `flyer_speed` | 82 → **219** |
| 字号 | `player_font_size` 等 4 个 | 40/34/34/22 → **×2.667** |
| 坐标 | HUD 里所有像素坐标/尺寸 | ×2.667（或改成按视口比例布局） |
| **不动** | `vanish_time` 2.6 · `coyote` 0.10 · `jump_buffer` 0.12 · `invuln` 0.35 · 各种 cooldown · 掉落阈值(格) · 伤害(心) | **全部不变** |

**校验**：跳跃高度 = v²/2g = 1387²/(2×4000) = 240.5px ÷ 128 = **1.88 格**（和现在一模一样 ✓）
滞空 = 2v/g = **0.69s** ✓ 水平距离 = 667×0.69 = 460px = **3.6 格** ✓
→ 所有按"格"写的地形约束和回归断言**依然成立**。

### 5.3 还要做的两件小事

1. **开启 mipmap**：`project.godot` 的 `[importer_defaults] texture={"mipmaps/generate": true}`，
   并把 `rendering/textures/canvas_textures/default_texture_filter` 设为 **Linear Mipmap**。
   改完要删 `.godot/` 重新导入一次。
2. **加载器支持子目录**：图在 `assets/art/textures/`，我的 `Assets.get_art()` 只扫
   `assets/art/`，加一层子目录搜索即可。

## 6. 斜坡 + 梯子（都做，但有回退闸）

你说了要，我也认为有意思。关键是**用最安全的方式引入**。

### 6.1 斜坡：不改变几何的引入法 ★

`tile_slope` 是 45° 斜坡。**我的地形里"相邻两列高度差正好 1 格"就是 45°** ——
所以规则是：**凡是地表出现了 1 格落差的地方，就把台阶换成斜坡**。

```
现在是:   ██████         改成:   ██████
              ██████                 ╱██████
```

这样：
- **可通行性完全不变**（本来就是能跳上去的 1 格台阶，现在变成能走上去的坡）→ 手感只会更好
- **现有地形约束（台阶 ≤1 格）和回归测试依然有效** ✓
- 不引入"跳不过去"的新风险

**要改的**：斜坡格用 `CollisionPolygon2D` 三角形；玩家 `floor_max_angle` 设 46°。
**风险**：中。`CharacterBody2D` 在斜面上有"下滑 / 抖动"两个经典毛病，
需要配 `floor_snap_length` 和"上坡不减速"处理。→ **单独一个 commit，做不顺手立刻回退。**

### 6.2 梯子

- 新增格子类型 `LADDER`（不参与碰撞方块，单独一层 `Area2D` 检测）
- 玩家新增"爬梯状态"：进梯关重力、上下匀速、按跳跃脱离、出梯恢复
- 放置位置：断崖边缘（**掉下去能爬回来**）、塔内部、可进入的城堡里
- **风险**：中（状态机要和现有的跳跃/骑怪/掉落伤害共存）。
  → 也**单独一个 commit**，不行就只保留"结构里的装饰梯子"（能看不能用）。

> 你的原话我记下了：**感觉难就立刻退回上一版本，不硬做。**
> 我的执行方式是：斜坡、梯子各自独立 commit，随时可 `git revert` 那一个；
> 主力功能（地图细节、生物群系、结构）永远在主干上，不受它们拖累。

## 8. 素材复用：真正的瓶颈不是纹理，是节点

你问"Godot 是不是已经搞了"——**是，纹理这块完全不用担心**：

1. Godot 的 `ResourceLoader` **按路径缓存**：同一个 `tile_stone.png` 加载 500 次
   返回的是**同一个 `Texture2D` 实例**，内存里只有一份。
2. 我的 `Assets.get_art()` 还额外做了字典记忆。

**真正会爆的是节点数和 draw call**：

| 方案 | 现状 | 复杂地图（厚地体+装饰+建筑）会怎样 |
|---|---|---|
| 现在：每格一个 `SolidTile` 节点 | ~500 个节点 | 涨到 **3000~6000 个节点**（含碰撞体）→ 卡 |
| **推荐**：地形**单节点自绘** + 碰撞体**贪婪合并** | — | **1 个渲染节点 + ~80 个碰撞体** |

**推荐做法的细节**：

- **渲染**：一个 `TerrainRenderer` 节点，在 `_draw()` 里只画可见格子
  （`draw_texture_rect` + 每格 tint + 三阶段消失状态）。
  这和我现在的 `GridBackground` 是同一个套路，我熟；一屏约 400~800 次绘制，很轻。
- **碰撞**：把同一行的连续实心格**合并成一个大矩形**（贪婪合并），
  碰撞体从 ~500 降到 ~80。碰撞体只在刷新时重建。
- **特效**（碎片、虚线残影、偏旁浮出）仍然是**临时小节点**，用完即毁。
- 好处：节点数与地图复杂度**基本脱钩**，可以放心把地图做厚做密。

> 这一步是"复杂地图"的地基。不做它，地图一复杂就卡（上一轮那个"越玩越卡"就是同源问题）。

## 11. 需要你拍板的 4 件事

1. **「只有一个偏旁」你指的是哪个意思？**
   - (a) **视觉简化**：偏旁的图像简化为"单个黑白偏旁字"（我按这个理解做的方案）
   - (b) **规则简化**：玩家同时只能带 1 个偏旁（那会砍掉槽位和组合技系统）

2. **11 个字全黑白之后，靠什么区分？** 我建议：**灰度档（每个字固定明度）+ 砖的边框样式**。
   你也可以选"黑白为主、每个字只留一点点淡色"（更易读但不够纯）。

3. **彩色汉字敌人要不要"脸"？** 参考图里的角色都有小眼睛笑脸。
   - (a) 纯字，无脸（最"书法"，最冷）
   - (b) 字 + 两只小眼睛（更活、更好笑，贴近参考图）

4. **斜坡我先做还是先不做？** 我的方案是"只在 1 格落差处换斜坡"，理论上零风险、
   收益明确；但 `CharacterBody2D` 在斜面上有下滑/抖动两个经典坑。
   你如果觉得"这轮别冒险"，我就把它放到最后一个独立 commit 里，
   做不好直接 revert，前面的东西一点不受影响。

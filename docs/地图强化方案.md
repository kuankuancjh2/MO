# 地图强化方案（用上 assets/art/textures 的素材）

> 素材：`assets/art/textures/`，172 张，128×128，手绘描边风。
> 本文只谈**地图生成怎么强化**，以及每一条用哪些素材、改哪个文件、有什么代价。

---

## 0. 先说我看到的（盘点结论）

### 0.1 风格：这是「单色描边稿」，是给你着色的

我抽看了地面、桥、结构、装饰、危险物、背景、角色、UI 各类共 16 张。结论：

| 类别 | 颜色 | 说明 |
|---|---|---|
| **地形 / 建筑 / 道具 / UI（绝大多数）** | **白填充 + 黑描边 + 浅灰内部细节** | **没有固有色** —— 是设计成**用 modulate 着色**的 |
| `background_cloud* / background_tree*` | 只有浅灰，**没有黑描边** | 视差剪影用（要压暗、低对比） |
| `character_round/square/rectangle/hand_*` | **预上色**（红/绿/紫/黄） | 带笑脸的角色，文件名自带颜色 |

**这件事很关键**：白色素材 + 我的 `AssetConfig` 配色系统 = 我可以让**同一张 `tile_stone.png`
在草原是青灰、在沙漠是暖黄、在遗迹是紫**，不需要美工画三套。这是本次强化最大的杠杆。

### 0.2 素材的"锚点"不统一（画的时候要注意）

| 素材 | 主体在画布里的位置 |
|---|---|
| `tile_*` 填充类 | 铺满整张 128×128 |
| `tile_bridge` / `bridge_walkway` | **只有顶部一条薄板**（约 128×32），下面全透明 |
| `tile_spikes` | **贴底**（约 128×48 在底部） |
| `bridge_arch` | 铺满，中间挖了个拱洞 |
| `column` / `tower` | 竖向长条，铺满高度 |

→ 绘制时要按各自锚点对齐（桥/钉刺是**贴单元格上下边**，不是居中）。

### 0.3 文件层面要收拾的小问题

| 问题 | 例子 | 处理 |
|---|---|---|
| 文件名带空格和括号 | `item_shield (2).png`、`item_sword (2).png` | 改名为 `item_shield_2.png` |
| 大小写重复 | `character_roundGreen.png` 与 `character_round_green.png` 同时存在 | 删一份 |
| 在子目录里 | 图在 `assets/art/textures/`，而我的加载器只扫 `assets/art/` | 加载器加子目录搜索（一行），或把图移上来 |
| 数量 | 172 张 | 我大概会用 **45~60 张**，其余先躺着（不删，留着以后用） |

### 0.4 我抽看的清单（按我关心的顺序）

`tile_stone` · `tile_top` · `tile_brick` · `tile_grass` · `tile_sand` · `tile_water` ·
`tile_bridge` · `bridge_walkway` · `bridge_arch` · `tile_slope` · `tile_diagonal` ·
`tile_spikes` · `tile_ladder` · `tile_bush` · `tile_chest` · `tile_coin` ·
`column` · `tower` · `castle` · `archway_small` · `roof_roundA` ·

## 1. 核心判断：我现有的地形生成**天然对得上**这套素材

我现在的 `TerrainGen` 已经算出了三件这套素材正好需要的东西：

| 我已经有的 | 素材需要的 |
|---|---|
| `column(cx,k).x` = 岛 / 桥 / 空 | 岛的填充 vs 桥的构件 |
| `is_surface(cx,cy)` = 是不是"地表那一行" | `tile_grass`（草皮）vs `tile_stone`（内部）—— **就是自动拼接** |
| 缺口两端的岛 `left` / `right` | 桥的立柱放哪、拱放哪 |

**所以这不是"重做地图"，而是"给已有的生成结果套上材质词汇"。** 这一点让整件事的性价比很高。

## 2. 地图强化方案（8 层，按性价比排序）

### L1 ★ 生物群系分区（Biome）—— 最大的一步

**问题**：现在整张地图是同一种深灰方块。走 5 分钟之后，玩家说不出"我在哪"。

**方案**：用一条**低频噪声**把横向空间切成若干"材质区"，每个区有自己的
「地表砖 + 内部砖 + 装饰 + 色调 + 危险物」：

| 区 | 地表砖 | 内部砖 | 装饰 | 色调 | 危险物 |
|---|---|---|---|---|---|
| **草原** | `tile_grass`（锯齿草） | `tile_stone` | `tile_tree` `tile_bush` | 青绿 | 少 |
| **沙地** | `tile_sand`（沙丘波纹） | `tile_sand` | `cactus` `pottery` | 暖黄 | 钉刺 |
| **石城** | `tile_top` | `tile_brick` | `column` `window` `tile_castle` | 冷灰 | 炮台 |
| **遗迹** | `tile_diagonal` | `tile_diagonal` | `obelisk` `archway_small` | 紫暗 | 锯片 |

- 选法：`biome_at(cx) = fbm1(cx * 0.012)` 分 4 档 → 每个区横向约 **100~200 列**
  （差不多 2~4 屏），走一段就"换地图"，但不至于碎。
- 和现有的桥/岛逻辑**完全正交**：先决定"这一列是不是岛"，再决定"这个岛长什么材质"。
- 技术上：给列缓存再加一个 `biome` 字段（缓存值从 `Vector3i` 换成小数组即可）。

> 这一步做完，地图的"横向旅程感"会立刻出来 —— 从草原走到沙地再走进遗迹。

### L2 ★ 自动拼接（地表 vs 内部）—— 零成本，立竿见影

`is_surface(cx,cy)` 我已经有了，直接：
- **地表那一行** → 该区的 `surface` 砖（草皮/沙面/顶线）
- **下面 1~2 行** → 该区的 `fill` 砖（石头/砖）

再加一个小技巧：**岛的底面把 `tile_top` 垂直翻转**当"岛底"用（`flip_v = true`），
浮岛的底部就有了收口，而不是生硬的直角。

> 为什么不做"左右边缘/四角"那套完整 autotiling：**这套素材每个方块都自带四边描边**，
> 摆在一起本来就是对的，做过度的边缘拼接反而画蛇添足。

### L3 ★ 桥的"三件套"—— 桥不再是薄板

我现在已经有"这一列是桥 + 缺口左右两端是谁"。据此把桥拆成构件：

| 位置 | 素材 | 视觉 |
|---|---|---|
| 缺口两端 | `bridge_column` | 桥墩 |
| 桥面 | `bridge_walkway` | 走道（薄板，对齐单元格顶部） |
| 桥面下方 | `bridge_arch` / `bridge_arch_bottom` | 拱形支撑（悬空 1~2 行） |

> 效果：从"一条细木板"变成**一座真的桥**。而且这是纯视觉 + 少量新节点，**不动碰撞**。

### L4 ★ 结构组件化 —— 用真素材重建结构

我的结构系统（字符网格）不用改，只是把字符扩成"素材构件"，并新建一批结构：

| 新字符 | 素材 | 用途 |
|---|---|---|
| `R` | `roof` / `roof_roundA..E` / `roof_round_half` | 屋顶（替换现在用 `#` 拼的三角屋顶） |
| `C` | `column_top/middle/bottom` / `column_wide` | 立柱 |
| `A` | `archway_small` / `archway_small_decorative` | 拱门（含 `doorway_open/closed`） |
| `V` | `window` / `window_round` / `window_decorative` | 窗 |
| `T` | `tower` / `tower_base` / `tower_top` / `tower_roof_*` | 塔（可以做成"要爬上去"的小关） |
| `L` | `tile_ladder` | 梯子（见 L8） |
| `U` | `tile_bush` / `tile_tree` | 地表植被 |
| `X` | `tile_spikes` | 钉刺 |
| `K` | `tile_crate` / `tile_chest` | 箱子（摸一下出东西） |

**顺带能新建的结构**（现在做不到的）：
- **爬塔**：`tower` 叠 + 内部 `tile_ladder` → 一个纵向小关，顶上有字
- **拱门大道**：连续 `archway_small` → 一条仪式感的长廊
- **城门**：`castle` + `castle_top` + `doorway_closed/open`（要用 `tile_key` 开）
- **废墟**：`obelisk` + `column_bottom`（断柱）+ `tile_bricks` 落石

### L5 装饰散布（按 biome 的散点表）

在每个"地表"格子上以小概率撒装饰：草区撒 `tile_tree / tile_bush`，
沙区撒 `cactus / pottery`，石城撒 `pole_lantern / carpet`。
**纯视觉，不参与碰撞**，但地图立刻"有人住过"的感觉。

> 关键：装饰也是**确定性随机**（和地形同一个 seed），所以卸载重载不会跳来跳去。

### L6 危险物按"规则"布点（而不是纯随机）

现在是"按概率随机撒怪"。有了素材可以做得更有设计感：

| 位置 | 放什么 | 素材 |
|---|---|---|
| 断崖（≥8 格的深渊）的**坑底** | 钉刺 / 水 | `tile_spikes` / `tile_water` |
| 平台**边缘**（相邻是缺口） | 钉刺 | `tile_spike` |
| 长桥的**中段** | 锯片来回 | `sawblade` |
| 石城区的高台上 | 炮台 | `cannon_small` + `bullet` |

> 原则：**危险物出现在"结构位置"上，而不是随机撒** —— 玩家能学会"坑底有刺、桥上有锯"。
> 这也让"掉到下一层"这条路更有风险，正好呼应你要的"掉下去是失误"。

### L7 视差背景（三层）—— 让岛"浮在世界上"

`background_cloudA/B`、`background_tree`、`background_treeLarge` 是**无描边的灰色剪影**，
正好做视差：

| 层 | 素材 | 视差系数 | 颜色 |
|---|---|---|---|
| 最远 | `background_cloudA/B` | 0.1 | 压到很暗 |
| 中 | `background_treeLarge` | 0.3 | 暗色剪影 |
| 近 | `background_tree` | 0.55 | 稍亮一点 |

技术上用 `ParallaxBackground` + `ParallaxLayer`（或我自己按相机位置画），
**tile 平铺 + 按 camera.x 取模**即可，无限延伸，零成本。

> 这是"便宜但改变观感"最大的一步：现在的地图像浮在虚空里，加完背景就是"一个世界"。

### L8 梯子 = 纵向连接（可选，看你要不要）

`tile_ladder` 让"掉下去"可以**爬回来**。放在两个地方：
- 深坑/断崖的边上（掉下去不是绝路）
- 结构内部（爬塔）

**代价**：要写"梯子状态"（进入梯子后关掉重力、上下移动、按跳跃脱离）。
大约 40 行代码 + 一个 `_on_ladder` 状态。**我建议先不做**，等你确认"掉下去要能爬回来"再加。

### L9 深坑注水（纯视觉，低风险）

`tile_water` 铺在断崖的**最底一行**。现在掉下去是"掉进虚空"，加一层水就是"掉进水里"，
落点心理感受完全不同。水面上还可以加 `smoke` 粒子。

## 3. 斜坡：最大的玩法升级，也是最大的风险

`tile_slope.png` 是一张真正的 45° 斜坡。加上它地图会从"楼梯"变成"丘陵"。

**但要付的代价**（我说清楚，你来决定）：
1. `CharacterBody2D` 现在只认"水平地面"：需要设 `floor_max_angle`、
   把斜坡格换成 `CollisionPolygon2D` 三角形（我现在全是 `RectangleShape2D`）。
2. 我现在**所有地形约束都是按"格子"算的**（台阶 ≤1 格、洞 ≤3 格）。
   有了斜坡，"台阶"概念要重新定义成"坡度"，回归测试里那两条断言要重写。
3. 玩家在斜坡上的"消失计时"要怎么算（踩到的是斜坡还是两格？）。

**我的建议**：**先不做**。理由：我这一版地图的核心命题是"横向连贯的岛 + 桥"，
斜坡是"更细腻的地形"，属于锦上添花；而它会把已经稳定的地形约束和测试搅乱。
等你玩过 L1~L7 之后，如果觉得"还是太像积木"，我们再上斜坡——那时我会给它专门一版
"坡度约束 + 测试"。

## 4. 角色素材怎么用（我的强烈建议）

`character_round/square/rectangle/hand_*` 是**预上色的笑脸角色**（4 色 × 4 形 = 16 张）。

**建议：主角不要用这些。**

原因很简单：**这个游戏的主角就是"莫"这个字。** 它会变成 慕/暮/漠/蟆/镆…
把主角换成一个红圆脸，整个游戏的立意就没了。

**建议这样分配**（正好我 4 种敌人）：

| 我的敌人 | 用它 | 理由 |
|---|---|---|
| 红方块怪（巡逻） | `character_square_red` | 方形 = 笨重巡逻 |
| 猎手（追人） | `character_round_red` | 圆形 = 滚动追击 |
| 飞怪 | `character_rectangle_red` | 扁长 = 能站上去（造型上"上面平"） |
| 红色偏旁怪 | `character_round_red` + **叠一个红色偏旁字** | 保留"红字"的辨识度 |
| **主角** | **保持「莫」字**（可选：底下垫一个 `character_round_*` 当身体） | 保住立意 |

> 主角如果想更好看，我可以做"**字 + 身体**"两层：底下用一个灰色 `character_round` 当身体，
> 上面浮着「莫」字。这样既有个性又不丢变字。

## 7. 一个需要你拍板的尺度问题：128px 素材 vs 48px 格子

素材是 128×128，我的格子是 48px。两条路：

### 选项 A：把素材缩到 48（缩放 0.375）—— 零风险
- 改一个数字，立刻能用。**代价**：黑描边从 ~4px 变成 1.5px，手绘的笔触感会损失大半。

### 选项 B：把整个游戏放大（格子 48 → 96，像素常量 ×2，相机 zoom 0.5）—— 推荐
- 视觉上**完全等价**：所有地形约束是按"格"算的（台阶 ≤1 格、洞 ≤3 格、跳跃 1.88 格），
  只要**像素常量全部 ×2**（跳跃初速、重力、移速、加速度、投射物速度、各种距离…），
  跳跃的**格数**不变、手感一模一样；再把相机 zoom 设 0.5，可见范围也一样。
- **收益**：素材用 0.75 缩放，手绘笔触完整保留。
- **代价**：一次机械但要全面的数值翻倍（我列了清单：约 20 个常量 + HUD 坐标 + 字体大小），
  且要重跑 60 项回归测试确认没崩。

> 我的建议：**先做选项 A 把功能跑通（今天就能看到效果），你确认图形方向后我再做选项 B 拉高画质。**
> 因为选项 B 是纯机械改动，随时可做、风险可控，不值得为它挡住内容进度。

## 8. 我建议的推进顺序

| 步 | 内容 | 为什么这个顺序 |
|---|---|---|
| 1 | 收拾文件名 + 加载器支持子目录 | 前置，10 分钟 |
| 2 | **L2 自动拼接 + L7 视差背景** | 性价比最高：不动生成逻辑就有质变 |
| 3 | **L1 生物群系** | 地图"旅程感"的核心 |
| 4 | **L3 桥三件套 + L4 结构组件化** | 现有结构立刻变好看，并能新建塔/城门 |
| 5 | L5 装饰 + L6 危险物布点 | 让地图"有人住过"、有设计感 |
| 6 | L9 注水（顺便） | 便宜 |
| 7 | 选项 B 画质放大 | 内容稳定后再动 |
| 8 | L8 梯子 / 斜坡 | 玩法向，等你说要不要 |

## 9. 需要你回答的 3 个问题

1. **主角要不要保持「莫」字？**（我强烈建议保持，`character_*` 全给敌人）
2. **先做选项 A（缩图，今天见效）还是直接上选项 B（放大全局，画质最好但要多一轮回归）？**

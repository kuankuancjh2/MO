### 为什么只有一个 .tscn？

节点结构全部在代码里搭（`Player.new()` 后在 `_ready` 里建子节点），场景文件只留一个根节点。
好处：场景文件不可能写错（手写 `.tscn` 很容易出格式错误），且美术完全由 `AssetConfig` 驱动。
代价：在编辑器里看不到节点树。要改回「编辑器友好」的结构时，把 `_ready` 里的建树代码
搬进 `.tscn` 即可，脚本接口不用动。

## 3. 五个 Autoload

| 名字 | 文件 | 职责 |
|---|---|---|
| `GameInput` | systems/game_input.gd | 用代码注册输入映射 |
| `Assets` | systems/assets.gd | 加载 `AssetConfig`，提供 `Assets.font` / `Assets.cfg` / `make_label()` |
| `Balance` | systems/balance.gd | 加载 `BalanceData`，`Balance.d.xxx` 访问所有数值 |
| `RunState` | systems/run_state.gd | 当局：金币、携带偏旁、槽位；死亡清空 |
| `MetaState` | systems/meta_state.gd | 局外：魂币、已购升级、最深纪录；存 `user://mo_save.json` |

> **输入为什么写在代码里？** `project.godot` 里的 `InputEvent` 序列化文本又长又容易写错，
> 而 `InputMap.add_action()` 一定生效、还能一眼看出绑了哪些键。

## 4. 数据驱动

### 4.1 偏旁：`RadicalData`

一个偏旁的全部能力由数据描述，逻辑层只读数据。

```
id / radical_char / composed_char / radical_position   # 氵 / 漠 / left
effect_type                                            # INSTANT 0 / ACTIVE 1 / PASSIVE 2
description / downside                                 # 给玩家看的文案
── 数值因子（正面与副作用共用同一套字段，1.0 = 无影响）──
vanish_slow_factor    >1 你的地面消失更慢     （副作用的写法就是 <1）
move_factor           <1 移速更慢
damage_taken_factor   <1 受伤更少
vision_factor         <1 视野变暗
attack_factor         >1 攻击更强
attract               磁吸开关
heal_on_pickup        拾取回血
── 主动技能 ──
skill_action          绑哪个键（"skill_1" = Q）
cooldown
── 组合技（预留）──
synergy_tags
```

> **关键设计**：副作用不单独写「坏字段」，而是直接用可正可负的**倍率**表达。
> 所以 `vanish_slow_factor = 20`（墓，好处）和 `= 0.5`（漠用完的限时惩罚）
> 走的是同一条代码路径，不需要分两套逻辑。

### 4.2 平衡参数：`BalanceData`

所有手感数值都在 `data/balance.tres`（或 `scripts/data/balance_data.gd` 的默认值）。
`data/balance.tres` 里只写了「与代码默认值不同」的项，所以文件很短 —— 这是 Godot 的正常行为，
**不是文件坏了**。改数值直接在编辑器里改这个资源。

### 4.3 新增一个偏旁的完整流程

1. 在 `devtools/gen_resources.gd` 的 `defs` 数组里加一行（id / 偏旁 / 字 / 类型 / 文案 / 颜色 / 数值）。
2. 删掉 `data/radicals/<id>.tres` 和 `data/radical_library.tres`，重跑生成器。
3. 如果效果纯数值 —— **完成，不用写一行代码**。
4. 如果需要额外逻辑（召唤、隐身、地形改造）—— 在 `radical_effects.gd` 加一个 `match` 分支。

```bash
Tools/Godot_console.exe --headless --path . --script res://devtools/gen_resources.gd
```

> 生成器会先 `ResourceSaver.save()` 每个偏旁，再 `load()` 回来放进总表，
> 这样 `radical_library.tres` 存的是**对外部文件的引用**而不是内嵌副本 ——
> 于是在编辑器里单独改一个偏旁的 `.tres` 会直接生效。

## 5. 无限地形（`terrain_gen.gd`）

### 5.1 结构

```
层带 k  覆盖行 [k*8, (k+1)*8)    每带一条厚 2 格的平台，其余为空
块      每 7 列为一个「块」，块内平台高度统一
```

`is_solid(cx, cy, seed)` 是**纯函数**：同样的坐标永远得到同样结果。
因此远处地块可以随便卸载，回头再看一模一样。

> 但「被莫抹掉的格子」必须额外记住（`GameWorld._destroyed`），否则卸载再加载会长回来。
> 这正是主题：**莫走过的地方，永久地归于无。**

### 5.2 三条硬约束（改地形必须遵守）

| 约束 | 值 | 依据 |
|---|---|---|
| 相邻块台阶落差 | ≤ 1 格 (48px) | < 跳跃高度 90px |
| 洞宽 | ≤ 3 格 (144px) | < 跳跃水平距离 173px |
| 相邻块的洞之间 | ≥ 2 格实地 | 防止洞拼成深渊 |

跳跃高度 = `v²/(2g)` = 520²/3000 ≈ 90px；滞空 = `2v/g` ≈ 0.69s；
水平距离 = 250 × 0.69 ≈ 173px。

**违反任何一条都会产生「跳不过去」的卡死点。** 冒烟测试第 1 节有专门的断言守着。

### 5.3 加载/卸载

`GameWorld._process` 检测主角是否移动超过 3 格（`REFRESH_MARGIN`，防抖），
超过就以主角为中心重建 `±24 列 × ±18 行` 的地块：矩形内的实心格实例化，矩形外的释放。
敌人与偏旁也在同一处按确定性随机生成（距离主角 > 8 格才刷，防止刷在脸上）。

## 6. 方块的消失动画（`solid_tile.gd`）

倒计时按 `Balance.d.vanish_time × player.vanish_factor` 计算（所以「暮」能让它变慢）。

| 进度 | 表现 | 目的 |
|---|---|---|
| 0 ~ 60% | 深灰 → 土黄渐变 | 「我刚才踩了这里」 |
| 60% ~ 90% | 转向危险红 + **闪烁频率随进度加快** | 「快没了」 |
| 90% ~ 100% | 缩小 40% + 淡出 + 留下虚线方框残影 | 「没了，这里现在是空」 |

`_draw()` 里用 `draw_set_transform()` 做整体缩放，用 `Time.get_ticks_msec()` 驱动闪烁
（不依赖帧率）。残影是独立节点 `VoidGhost`，0.55 秒后自毁。

## 7. 掉落伤害（`player.gd`）

记录腾空期间的最高点，落地时算落差：

```gdscript
if is_on_floor():
    if _airborne: _apply_fall_damage(global_position.y - _peak_y); _airborne = false
else:
    if not _airborne: _airborne = true; _peak_y = global_position.y
    _peak_y = minf(_peak_y, global_position.y)      # y 轴向下为正，所以取 min
```

```gdscript
tiles = 落差px / 48
if tiles <= 4.5: return                              # 短距离不受伤（普通起跳 1.88 格，永不触发）
dmg = min((tiles - 4.5) * 0.3, 1.5)                  # 每格 0.3 心，单次上限 1.5 心
if not fall_damage_lethal: dmg = min(dmg, hp - 1.0)  # 摔不死：永远留 1 心
```

**注意**：`fall_damage_lethal = false` 只保证「掉落伤害本身」不致死。
怪物仍然可以打死你 —— 这是有意为之。

## 8. ★ 换美术（不改代码）

**核心原则**：代码只引用语义（「主角色」「敌人色」），具体值全部通过 `Assets.cfg` 取。

### 8.1 三步换装

| 想改什么 | 改哪里 |
|---|---|
| 字体 | `assets/config/asset_config.tres` → `main_font`（留空则用系统字体，见 8.3） |
| 配色 | 同文件 → `color_*` 系列 |
| 方块贴图 | 同文件 → `solid_tile_texture` / `stepped_tile_texture`（留空则程序画方框） |

**不需要动任何 `.gd` 文件。**

### 8.2 代码里怎么取

```gdscript
Assets.font                                        # 全局唯一字体
Assets.cfg.color_player                            # 主角颜色
Assets.make_label("莫", 40, Assets.cfg.color_player)  # 造一个套好字体/字号/颜色的 Label
```

### 8.3 中文字体的坑

Godot 自带字体**不含中文**，直接渲染「莫/暮」会显示成空白或方块。
当前方案是 `use_system_font = true` + `SystemFont`（优先 Microsoft YaHei / SimHei / Noto Sans SC），
免打包、开箱即用。**但导出到别的平台（尤其 Web）时必须把字体文件打进包里** ——
那时在 `asset_config.tres` 的 `main_font` 里指定一个 `.ttf` 即可。

### 8.4 音效（待做）

`assets/audio/` 已规划目录，命名固定（jump / vanish / coin / hit / transform），
直接替换同名文件即可。

## 9. 踩过的坑（重要，别再踩）

### 9.1 物理体必须「入树前」定位 ⚠️

```gdscript
# ✗ 错：主角会以 (0,0) 注册进物理世界，而 (0,0) 往往在方块内部，
#     物理引擎把它「解穿透」弹飞 —— 实测瞬移 419px、速度 18741px/s
player = Player.new()
add_child(player)
player.global_position = spawn_point()

# ✓ 对
player = Player.new()
player.position = spawn_point()
add_child(player)
```

这个坑同样适用于敌人、金币、投射物、残影 —— 本项目所有生成点都已按正确写法修正。

### 9.2 不能在碰撞回调里往场景树加物理体 ⚠️

被投射物打死的敌人如果在 `_on_body_entered` 里直接生成金币（Area2D + 碰撞体），会报
`Can't change this state while flushing queries`。正确做法是交给父节点延迟一帧：

```gdscript
parent.call_deferred("add_child", coin)
```

### 9.3 地形必须保证可通过 ⚠️

见 5.2。第一版地形让每列高度随机起伏 0~2 格，结果主角走两步就被 2 格台阶卡住
（2 格 = 96px > 跳跃高度 90px）。改地形后一定重跑冒烟测试。

### 9.4 `move_and_slide()` 会回写 `velocity`

Godot 4 的 `move_and_slide()` 会把「实际位移 / delta」写回 `velocity`。
所以调试时看到莫名其妙的大速度，先怀疑解穿透，而不是自己的加速代码。

### 9.5 冒烟测试自己的两个坑

- 测试里让主角长时间待在世界里时，**怪可能把他打死**，之后所有断言都在尸体上跑
  （`heal()` 对死人是直接 return 的）。所以单元级检查要么清场，要么同步执行不等待。
- `_invuln`（受击无敌 0.35s）会让连续的伤害断言静默失效，测试里直接清零再断言。

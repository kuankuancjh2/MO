## 4. 数据驱动

### 4.1 字：`RadicalData`

```
id / radical_char / composed_char / radical_position
effect_type            # INSTANT 0 / ACTIVE 1 / PASSIVE 2
description / downside
── 数值因子（1.0 = 无影响；正面与副作用共用同一套字段）──
vanish_slow_factor    >1 地面消失更慢
move_factor           <1 移速更慢
damage_taken_factor   <1 受伤更少
vision_factor         <1 视野变暗
attack_factor         >1 攻击更强
attract / heal_on_pickup
── 主动技能 ──
skill_action / cooldown
── 组合技（预留）──
synergy_tags
```

> 副作用不写"坏字段"，用**可正可负的倍率**表达。所以 `vanish_slow_factor = 20`（墓）
> 和 `= 0.5`（限时惩罚）走同一条代码路径。

### 4.2 结构：`StructureData`

```
id / grid: PackedStringArray / weight / tags
```

`grid` 是一张字符网格。**最后一行对齐"玩家身体行"**（平台顶上一格），往上依次是 -2、-3…

| 字符 | 含义 |
|---|---|
| `#` | 实心方块 |
| `W` | 字块（实心，撞碎得字） |
| `E` / `K` / `F` / `R` | 巡逻怪 / 猎手 / 飞怪 / 红偏旁怪 |
| `S` | 商店 |
| `.` | 空 |

### 4.3 新增一个字的流程

1. `devtools/gen_resources.gd` 的 `defs` 里加一行。
2. 删 `data/radicals/<id>.tres` 与 `data/radical_library.tres`，重跑生成器。
3. 纯数值效果 → **完成，不用写代码**；要额外逻辑 → 在 `radical_effects.gd` 加 `match` 分支。

### 4.4 新增一个结构的流程

在 `gen_resources.gd` 的 `struct_defs` 里加一张网格即可。
**唯一硬性要求：最后一行（地面层）必须左右贯通**，否则玩家会被卡死。

## 5. 地形与结构（`terrain_gen.gd`）

### 5.1 生成模型

```
层带 k   覆盖行 [k*8, (k+1)*8)   每带一条厚 2 格的平台
块       每 11 列一个块，块内平台高度统一（0 或 1）
结构     每 34 列一个槽位，55% 概率嵌一个结构
```

`is_solid(cx, cy, seed)` 是**纯函数**（同样坐标 → 同样结果），所以地块可以随便卸载重载。
但「被莫抹掉的格子」记在 `GameWorld._destroyed`，卸载再加载不会长回来 ——
**莫走过的地方，永久地归于无。**

### 5.2 三条硬约束（改地形必须重跑测试）

| 约束 | 值 | 依据 |
|---|---|---|
| 台阶落差 | ≤ 1 格 (48px) | < 跳跃高度 90px |
| 洞宽 | ≤ 3 格 (144px) | < 跳跃水平距离 173px |
| 相邻块的洞间距 | ≥ 2 格实地 | 防止拼成深渊 |
| **结构地面层** | **必须贯通** | 玩家只向右走，死路 = 卡死 |

跳跃高度 = `v²/2g` = 520²/3000 ≈ 90px；滞空 = `2v/g` ≈ 0.69s；水平距离 = 250 × 0.69 ≈ 173px。

冒烟测试第 1 节有断言守着台阶与洞宽；结构贯通由 `gen_resources` 的网格约定保证。

### 5.3 结构如何"长"进地形

`TerrainGen.struct_cell(cx, cy, s) -> String` 负责回答"这一格属于某个结构吗、是什么"：

1. 算层带 k → 得到该层带的平台顶行 `base_row`。
2. 算结构槽位 `si = fdiv(cx - MARGIN, SPAN)`，检查槽位 `si` 与 `si-1`（结构可能跨槽位）。
3. 网格行号 `gr = height + (cy - base_row)`；`row == 0`（平台顶行）强制返回 `#` 作为**地基**，
   保证结构不会因为地形开洞而悬空。

`is_solid` 先问 `struct_cell`，非空则按 `#`/`W` 判定实心，**结构优先生效**。

### 5.4 加载/卸载（含性能修复）

`GameWorld._process` 检测主角移动超过 3 格就重建 `±24 列 × ±18 行` 的地块，并：

- **卸载矩形外的方块、敌人、字块、商店**（从字典移除 + `queue_free`）——这是性能问题的根因，见第 10 章。
- 矩形内的实体按"格坐标"字典去重生成，所以卸载再加载不会重复。

## 6. 方块与字块

### 6.1 `SolidTile`

倒计时 = `Balance.d.vanish_time × player.vanish_factor`。三段可视化：

| 进度 | 表现 |
|---|---|
| 0~60% | 深灰 → 土黄 |
| 60~90% | 转红 + 闪烁频率随进度加快 |
| 90~100% | 缩小 40% + 淡出 + 留下 `VoidGhost` 虚线方框 |

**性能**：`_ready` 里 `set_process(false)`，只有被碰到时才 `set_process(true)` ——
不然几百块砖每帧都跑一次 `_process`。

### 6.2 `WordBlock`（字块）

- `StaticBody2D`，砖面用 `_draw` 画字（`draw_string`），颜色取自该字。
- 被玩家碰到 → `CRUMBLING` 0.25 秒 → 碎片飞散 → 授予该字 → `queue_free`。
- 因为是实心的，**撞碎之前会挡路** —— 通行与拾取是同一个动作。

## 7. 怪物

### 7.1 共同基类 `EnemyBase`

`hp / contact_damage / stomp-able / 掉落金币 / 受击闪白 / 接触冷却`。

**接触伤害统一由主角判定**（不用 Area2D）：
`Player._physics_process` 里遍历 `move_and_slide()` 的碰撞，对每个敌人碰撞体：

```gdscript
if normal.y < -0.6 and velocity.y > 0:   # 从上方落下 = 踩头
    enemy.on_stomped(self)               # 地怪死 / 飞怪被驯服
else:
    enemy.try_contact_damage(self)       # 否则掉血（敌人自带 0.8s 冷却）
```

这样一次遍历同时处理"踩"和"碰"，还顺手省掉每个敌人一个 Area2D（性能）。

### 7.2 三种敌人

| 类 | 行为 |
|---|---|
| `RedBlock` | 地面巡逻，`is_on_wall()` 或悬崖预判（`RayCast2D`）时转身 |
| `Seeker` | 追玩家：水平朝玩家加速；撞墙且在地面时跳一下；会走下悬崖 |
| `Flyer` | **`AnimatableBody2D`**，无重力，平滑追向玩家 |

### 7.3 飞怪为什么是 `AnimatableBody2D`

它是**移动平台**：`collision_layer = 1 | 4`（1 = 玩家会把站上去的东西当"地板"并接受其速度，
`CharacterBody2D.platform_floor_layers` 默认就是 layer 1），`collision_mask = 0`（穿过地形）。
所以驯服后玩家站在它上面会被自动带着走，不需要手写"跟随"逻辑。

驯服逻辑：`on_stomped()` → `tamed = true`，`tamed_left = 6s`，此后水平朝玩家朝向飞。

## 8. 掉落伤害与卸力（`player.gd`）

记录腾空期的最高点，落地时算落差：

```gdscript
tiles = 落差px / 48
if tiles < 4.5:  return                       # 安全
if tiles < 10.0 and _landing_cancel_ok():     # 落地前 0.22s 内按过跳跃
    return                                    # 卸力成功
take_damage(1.0, "fall")                      # 否则固定扣 1 心
# take_damage 里：if not fall_damage_lethal: dmg = min(dmg, hp - 1.0)
```

- `_landing_cancel_ok()`：落地前 `fall_landing_cancel_window`（0.22s）内按下过跳跃。
- **危险下落时主角字形变红闪烁**作为提示（否则玩家不知道何时按）。
- 卸力成功弹「卸力」提示。
- `fall_damage_lethal = false` 只保证"掉落"不致死；**怪仍然能打死你**，这是有意的。

## 9. 音频：怎么往里放文件 ✔

系统已就绪，**只差文件**。

### 9.1 放文件

把音频丢进 `assets/audio/`，用下面这些**固定文件名**（后缀 `.ogg` / `.wav` / `.mp3` 都行）：

| 文件名 | 触发时机 |
|---|---|
| `jump` | 起跳 |
| `land` | 落地 |
| `vanish` | 方块消失 |
| `stomp` | 踩死怪 |
| `shatter` | 字块碎裂 |
| `transform` | 变成新字 |
| `hit` | 主角受击 |
| `coin` | 吃金币 |

例如放一个 `assets/audio/jump.ogg` 就立刻有起跳音效，不用改代码、不用重启编辑器之外的任何配置。

### 9.2 代码里怎么用

```gdscript
Sfx.play("jump")        # 找不到文件就静默跳过
```

`Sfx` 是 autoload，启动时每个名字查找一次 `assets/audio/<name>.{ogg,wav,mp3}`；
找不到就记下来、只 `print` 一次提示，运行中直接 no-op。
多声道池（默认 8 个 `AudioStreamPlayer`）轮转播放，避免同帧音效互相打断。

### 9.3 想加新音效

在 `scripts/systems/sfx.gd` 的 `NAMES` 数组里加一个名字，然后放同名文件。

## 10. 性能（"玩久了越来越卡"的根因与修复）✔

### 10.1 根因

`GameWorld._refresh` 只卸载了**方块**，**敌人、字块、商店从来没被卸载**
（`_enemies` / `_pickups` 字典只增不减，节点永久留在场景树里）。
于是玩家一路向右，身后留下一串永不释放的怪 —— 每个都带 `_physics_process`、
`_draw`、碰撞体。节点数线性增长 → 越来越卡。
**重开一局就恢复**，因为整个场景被重建了 —— 这正是"泄漏"的典型特征。

### 10.2 三处修复

| 修复 | 说明 |
|---|---|
| 卸载矩形外的实体 | 遍历 `_enemies`/`_pickups`，出界的 `queue_free` 并从字典 `erase` |
| 实体生成按格去重 | `_spawn_entities` 只在"该格还没有实体"时生成，卸载重载不会翻倍 |
| 砖块默认关闭 `_process` | `SolidTile._ready` 里 `set_process(false)`，被碰到才开 |
| 敌人只在需要时重绘 | 受击闪白/转向时才 `queue_redraw()`，不再每帧重绘 |
| 背景只在相机移动时重绘 | 记录上次相机格坐标，没动就不重绘 |

### 10.3 回归测试

冒烟测试第 7 节：把主角连续瞬移 20 次（每次 20 格）强制触发 20 次重载，
断言世界里**总节点数不超过上限**。修复前这个数会线性增长，修复后稳定。

## 11. 踩过的坑（别再踩）

### 11.1 物理体必须"入树前"定位 ⚠️

```gdscript
# ✗ 会以 (0,0) 注册进物理世界，(0,0) 常在方块内部 → 被解穿透弹飞 419px
add_child(player); player.global_position = spawn
# ✓
player.position = spawn; add_child(player)
```

### 11.2 不能在碰撞回调里往场景树加物理体 ⚠️

报 `Can't change this state while flushing queries`。用 `parent.call_deferred("add_child", node)`。

### 11.3 `move_and_slide()` 会回写 `velocity`

Godot 4 把"实际位移 / delta"写回 `velocity`。看到莫名的大速度，先怀疑解穿透。

### 11.4 地形/结构的可通过性

第一版地形每列随机起伏 0~2 格 → 2 格台阶 = 96px > 跳跃高度 90px → 走两步就卡死。
结构同理：一个四面封死的小屋就是死路。**改地形/加结构后一定重跑冒烟测试。**

### 11.5 冒烟测试自己的两个坑

- 主角长时间待在世界里时**可能被怪打死**，之后所有断言都跑在尸体上（`heal()` 对死人是 return）。
  单元级检查要清场或同步执行。
- `_invuln`（受击无敌 0.35s）会让连续伤害断言静默失效 —— 测试里直接清零再断言。

### 11.6 `AnimatableBody2D` 继承自 `StaticBody2D` ⚠️

用 `if node is StaticBody2D` 来区分"这个节点要不要我帮它设 position"时，
**飞怪和红偏旁怪（AnimatableBody2D）会被一起跳过** —— 它们的 position 永远是 (0,0)，
也就是全部生成在出生点旁边。表现是"主角一出生就被弹上天、很久不落地"。
正确做法是按具体类型判断（本项目改成 `if node is WordBlock`）。

### 11.7 字典里可能存着"已被释放的实例" ⚠️

```gdscript
var n: Node = _spawned[key]        # ✗ 报 "Trying to assign invalid previously freed instance"
var n = _spawned[key]              # ✓ 无类型接住，再 is_instance_valid 判断
```

### 11.8 怪死了要在原地"销号"

`_spawned` 的条目一旦被清掉，下一次刷新会在同一格**重新刷一个怪** —— 变成无限刷怪点。
所以实体被消耗（打死/撞碎）时要调 `GameWorld.consume_cell(self)`，
把出生格写进 `_destroyed`（同时也就不会再重生）。
